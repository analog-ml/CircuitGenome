Part 1 · Why this file even exists

The one job: be the pocket calculator of analog design — turn a transistor's current and size into its small-signal behavior (gm, gd, Vdsat), and turn those, in turn, into the numbers a spec sheet cares about (gain, bandwidth, phase margin, CMRR).

An op-amp sizer has to answer two very different kinds of question. First, the device question: "I've decided this transistor carries 100 µA and is 10× wide — so how strong is it, how leaky is it, how much voltage room does it eat?" Second, the circuit question: "given a handful of those devices wired into a two-stage amplifier, what gain and bandwidth do I actually get?"

Think of it as a two-shelf toolbox. The bottom shelf holds device primitives — tiny formulas from the 1968 Shichman–Hodges "square law," the simplest textbook model of a MOSFET. The top shelf holds op-amp metrics — the performance formulas every analog course writes on the board. The magic is that the top shelf only ever asks the bottom shelf for three things: gm, gd, and a capacitor. Nothing else.

There is no call graph in the usual sense — these are all leaf functions, pure math with no side effects. What matters is the data-flow the arrow shows: primitives produce numbers, metrics consume them.

Part 2 · One square law, and every equation that falls out of it

You need exactly one equation to understand this file. Here it is, and here is every formula derived from it — in one pass, up front.

IDS= µCox2 · WL · (VGS−Vth)2

Six moves from the parent equation

Each device primitive is this one equation rearranged, differentiated, or extended — three kinds of move, six results:

The same six moves in words, with the nuance the boxes cannot carry:

  1. Solve for the overdrive. Invert the parabola and a square root appears: overdrive = √(2·|I|·L / (µCox·W)). A Level-1 identity makes this also the minimum drain room the device needs to stay saturated — same number, two roles. → vds_sat
  2. Stack it on the threshold. To carry that current the gate must sit a threshold plus an overdrive above the source. → vgs_from_ids
  3. Differentiate. Take dIDS/dVGS and the square disappears, leaving gm = µCox·(W/L)·overdrive; substitute the overdrive back in terms of current and you get the √ form the code uses. → gm
  4. Cap it. The square law over-promises efficiency near weak inversion, where real physics holds gm/IDS ≤ 1/(n·φt) ≈ 25 /V. → gm_ceiling
  5. Add channel-length modulation. The square law's (1 + λ·VDS) correction says current sags with drain voltage; the slope of that sag is the output conductance gd = λ·|I|. → gd
  6. Parallel two leaks. A stage's output node is squeezed between a top load and a bottom drive device, both leaking into it; conductances in parallel add. → rout

Those six give the bridge to the top shelf: a stage's voltage gain is Av = gm · rout — strength times stiffness. From there, every metric is built from gm, gd, and a capacitor, and none of them mentions µCox, W/L, or Vth ever again.

Part 3 · The device primitives in code

gm — how strong is the transistor?

gm is the gain of a faucet: turn the handle a little (gate voltage), how much extra water flows (current)? In amps per volt, it is literally the slope of the square-law curve wherever you happen to be sitting.

def gm(mu_cox, w_um, l_um, ids_a) -> float:
    return math.sqrt(2.0 * mu_cox * (w_um / l_um) * abs(ids_a))

The consequence to remember: gm scales as √IDS, so doubling strength costs quadrupling current. That square-root wall is why analog designers obsess over efficiency — and why the next function exists.

gm_ceiling — the square law lies at the top

Pushed hard, the square law happily quotes an efficiency the device can only reach by sliding into weak inversion. The flat 25 /V roof (from n ≈ 1.5, φt ≈ 25.9 mV, matching measured gm/Id ≈ 25 on real PTM devices) is the honesty check a caller clamps against.

_GM_OVER_ID_MAX = 25.0

def gm_ceiling(ids_a) -> float:
    return _GM_OVER_ID_MAX * abs(ids_a)

gd — the pinhole leak

An ideal current source pushes the same current at any voltage. Real transistors aren't ideal — squeeze the drain and the channel shortens a hair, letting a little more current through. Think of a sealed tank with a pinhole. A short transistor has big λ (leaky); a long one has small λ (tight).

Conductance and resistance are one fact read two ways: r = 1/gd, and gd = 1/r. A device leaking gd = 10 µS is a 100 kΩ resistor from drain to source — same device, reciprocal units. Conductance is the form worth carrying here, because leaks that share a node add directly (gd_top + gd_bot) while resistances in parallel do not. That is exactly why rout below sums the conductances first and inverts once, at the end.

def gd(lam, ids_a) -> float:
    return lam * abs(ids_a)

rout — two leaks share one node

Both the top load and the bottom drive device leak toward the output node, exactly like two resistors in parallel.

def rout(gd_top, gd_bot) -> float:
    total = gd_top + gd_bot
    return 1.0 / total if total > 0.0 else float("inf")

The guard matters: a caller passing zero total conductance (a perfect, lossless node) gets inf rather than a division by zero — the honest answer for "infinite gain, if only the world were ideal." The stiffer the node, the more gain the stage delivers, since Av = gm · rout.

vds_sat and vgs_from_ids — the voltage room

Two questions, one square root: how much drain room does this device need to keep working, and how high must the gate be held to push this current?

def vds_sat(mu_cox, w_um, l_um, ids_a) -> float:
    return math.sqrt(2.0 * abs(ids_a) * l_um / (mu_cox * w_um))
def vgs_from_ids(mu_cox, w_um, l_um, ids_a, vth) -> float:
    overdrive = math.sqrt(2.0 * abs(ids_a) * l_um / (mu_cox * w_um))
    return math.copysign(abs(vth) + overdrive, vth)

One subtlety worth naming: math.copysign(..., vth). The magnitude is always |Vth| + overdrive, but the sign is copied from Vth — positive for NMOS, negative for PMOS. A two-character trick that makes one function correct for both device flavors.

Part 4 · The op-amp metrics in code

open_loop_gain_db — multiply the stages, speak in decibels

def open_loop_gain_db(stage_gains) -> float:
    product = math.prod(stage_gains)
    return 20.0 * math.log10(abs(product)) if product != 0.0 else -math.inf

One caveat about what this number means: it is a best case, not a prediction. It multiplies together each stage's ideal gm·rout and subtracts nothing for the losses a real amplifier pays — one stage loading the next, limited bias headroom, device mismatch. Read it as a ceiling the design cannot beat, not as the gain you would measure on the bench. Its companion open_loop_measurable() flags any result above the ~150 dB open-loop-bench ceiling (OPEN_LOOP_GAIN_CEILING_DB), where the output can no longer be held at mid-rail and the measured open-loop gain rails toward 0 dB.

unity_gain_bw — how fast before the gain runs out

The input pair pushes current gm1 into the compensation capacitor Cc; a bigger cap is a heavier flywheel that responds more slowly. Speed = push ÷ inertia.

def unity_gain_bw(gm1_a_v, cc_f) -> float:
    return gm1_a_v / (2.0 * math.pi * cc_f)

slew_rate_vps — the large-signal speed limit

The one job: how fast can the output ramp when the input steps hard and the tail current is all you've got to charge Cc?

def slew_rate_vps(ibias_a, cc_f) -> float:
    return ibias_a / cc_f

When the input step is big, the input pair fully steers the tail current IBias into Cc, and the output climbs no faster than that fixed current allows — a bucket brigade at a fixed pour rate. Notice the family resemblance: GBW and SR share the same Cc. Small-signal speed divides gm1 by it; large-signal speed divides the tail current by it. One capacitor sets both limits.

phase_margin_two_stage_deg — will it ring or settle?

Feedback is a promise to correct errors, but every stage adds delay, and delay is phase lag. If the signal comes back a full 180° out of step while the loop still has gain, the correction becomes reinforcement and the circuit rings. Phase margin is how far from that cliff you are at the unity-gain frequency — like pushing a swing: in time it grows smoothly, a half-cycle late you fight yourself.

def phase_margin_two_stage_deg(gm1, gm2, cc_f, cl_f) -> float:
    return 90.0 - math.degrees(math.atan(gm1 * cl_f / (gm2 * cc_f)))

Read it as "start at an ideal 90°, then subtract the lag from the non-dominant pole at gm2/CL." The closer that pole creeps to the unity-gain frequency, the bigger the arctan bite; push the second stage harder (bigger gm2) or lean on more Cc, and the lag shrinks. 60° is the usual target.

phase_margin_three_stage_deg — two lags to subtract

A nested-Miller three-stage amplifier has two non-dominant poles, so the same idea subtracts two arctan lags instead of one, both referenced to ωt = gm1/Cc1.

def phase_margin_three_stage_deg(gm1, gm2, gm3, cc1_f, cc2_f, cl_f) -> float:
    wt = gm1 / cc1_f
    lag2 = math.degrees(math.atan(wt * cc2_f / gm2))
    lag3 = math.degrees(math.atan(wt * cl_f / gm3))
    return 90.0 - lag2 - lag3

cmrr_db — how well it ignores common junk

A differential pair rejects common-mode noise only as well as its tail current source is stiff. A perfect tail (gd_tail = 0) rejects it infinitely — hence the inf guard. Real tails leak.

def cmrr_db(gm1, gd_tail) -> float:
    if gd_tail == 0.0:
        return math.inf
    return 20.0 * math.log10(gm1 / (2.0 * gd_tail))

psrr_db_approx — how well it ignores a noisy supply

Same shape, different players: second-stage strength over the bias transistor's leak. The docstring is refreshingly honest — it flags itself as a rough first-order estimate and says accurate PSRR needs simulation.

def psrr_db_approx(gm2, gd_bias) -> float:
    if gd_bias == 0.0:
        return math.inf
    return 20.0 * math.log10(gm2 / gd_bias)

quiescent_power — the idle electricity bill

The plainest formula in the file, summed over every branch drawing from the supply.

def quiescent_power(vdd, vss, supply_currents_a) -> float:
    return (vdd - vss) * sum(abs(i) for i in supply_currents_a)

Part 5 · The hidden idea, and the honest limits

Look back at the catalog in Part 2. Every metric is built from gm, gd, and a capacitor — and not one of them mentions µCox, W/L, or Vth. The device physics vanishes the moment you cross from the bottom shelf to the top. That is not an accident; it is the whole architecture.

metric= F( gm, gd, C) — independent of how gm was found

This is why the square-law primitives and the measured gm/Id lookup table can live behind one shared DeviceModel interface. For the card-less generic tech you compute gm from the square law in this file; for a real PTM node you read gm off a characterized table. The performance formulas never notice the difference.

What this file honestly does not do

  • The primitives are Level-1 square law — a teaching model. Real short-channel devices (BSIM) show velocity saturation, mobility degradation, and a soft weak-to-strong transition the square law can't capture. That's exactly why the PTM path uses a measured LUT instead.
  • gm_ceiling is a blunt patch (a flat 25 /V cap) bolted on because the square law over-promises efficiency near weak inversion.
  • The metric formulas are single-/dominant-pole approximations: internal mirror poles are neglected, PSRR is explicitly labeled rough, and phase margin assumes a clean pole ordering. They size the first cut; SPICE grounds the final verdict.
  • Every function is pure arithmetic with SI-unit assumptions baked into the names — pass millimetres where micrometres are expected and it will happily return nonsense.

In one sentence: equations.py is a two-shelf calculator — the bottom shelf rearranges one Level-1 square law into gm, gd, and Vdsat, and the top shelf turns those three (plus a capacitor) into every op-amp spec — gain, bandwidth, phase margin, slew rate, CMRR, PSRR, power — with the deliberate design that the performance math is model-independent, so square-law and measured gm/Id devices flow through the exact same formulas.
