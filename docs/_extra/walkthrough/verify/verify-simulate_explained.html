Part 1 · Why this file exists

TLDR: simulate_metrics() builds the DUT once, runs six independent benches over it in an order set by the two facts the AC sweep discovers, and returns the same nine keys the analytical estimate uses — with None wherever a measurement could not be made, and a note saying why.

Main task: run all six benches on one circuit and return one dictionary — without ever letting a failed bench take down the ones that would have worked.

Ninety-five lines, almost all of them about failure.

The real work happens elsewhere: deck.py builds the DUT, rig.py wraps it, measure.py measures it. This file's contribution is the discipline around those calls — the order they run in, what gets shared between them, and what happens when one of them doesn't work.

That last part is most of the file, and it is not incidental. ngspice fails to converge on real circuits for real reasons. A verification pass that raises on the first non-convergence is useless for a designer sweeping thousands of candidates: one awkward circuit and the whole run dies.

six benches → nine keys, some possibly None, plus notes

Part 2 · Nine keys, pre-declared

The one job: promise the caller a fixed set of keys, whatever happens.

The output dict is written out in full before a single simulation runs:

out = {
    "power_w": None, "gain_db": None, "gbw_hz": None,
    "phase_margin_deg": None, "slew_rate_vps": None,
    "output_swing_max_v": None, "output_swing_min_v": None,
    "cmrr_db": None, "psrr_db": None,
}

Two consequences fall out of that one decision.

First, the keys mirror evaluate_metrics() exactly — the analytical estimate and the measurement speak the same vocabulary, so comparing them is a dict lookup rather than a translation layer. That is the whole point of the package.

Second, a caller never has to ask whether a key exists. It always does. The only question is whether it is None, and None has exactly one meaning throughout:

None means "not measured". It never means "measured as zero".

An amplifier with no gain and an amplifier whose gain measurement failed are very different findings, and collapsing them into 0.0 would lose that distinction permanently.

Part 3 · Every bench in its own try

The one job: a bench that throws should cost you that one metric, and nothing else.

def _oops(bench, e):
    notes.append(f"{bench} bench failed: {type(e).__name__}: {e}")

try:
    out["power_w"] = _measure_power(*args)
except Exception as e:
    _oops("power", e)

That pattern repeats for all six. It is deliberately the broadest possible catch, and the exception type and message are preserved in the note rather than discarded — so a failure is visible and debuggable without being fatal.

Part 4 · What the benches share, and the order that forces

The one job: the benches are independent, but two facts have to travel between them — so the running order is not arbitrary.

Everything common is computed once, up front, and passed as a tuple:

name, ports, body = _parse_subckt(netlist_text)
unsized = unsized_mos_refs(body, result)
body    = _inject_sizes(body, result)
body_dut = _dut(tech, name, body, corner)
args = (name, ports, body_dut, _Topo(ports), vdd, ibias, vcm)

One DUT block, built once, reused by all six. But two things are discovered rather than computed, and both come out of the AC bench:

DiscoveredWho needs itWhat happens without it
polarityslew, swing, CMRR, PSRReach would re-run the polarity search itself
ac_cleanCMRR, PSRRratios against a corrupt Adm

Hence the order: AC runs second, right after power, and everything that depends on it comes later. Slew and swing accept polarity=None and fall back to trying both, so they still run if AC failed — but CMRR and PSRR are hard-gated:

# CMRR/PSRR are relative to the differential gain: without a clean Adm
# measurement the ratio is garbage-on-garbage, so they stay None.
if ac_clean:
    …

Note what ac_clean means: reason is None — not merely that the AC bench returned a number. A circuit measured at −3 dB gain returns a perfectly real number with a reason attached, and that is not a basis for a rejection ratio.

The extra key

When anything has gone sideways, one more key appears:

if notes:
    out["notes"] = notes   # advisory, not a metric

It carries bench failures, the unsized-MOSFET warning, and — when the AC sweep found no gain — the bias diagnostic from op.py explaining which devices were in triode. It is the only key that is not a number, and the only one that is sometimes absent.

Part 5 · What it honestly does not do

  • It does not judge. Nothing here compares a measurement to a spec; that is the caller's job. This function reports what the circuit did.
  • It runs one corner per call. Sweeping corners means calling it repeatedly with different corner values — which is exactly what the CLI does.
  • Six benches means six ngspice launches. Deliberate, but it makes this the slowest thing in the pipeline by a wide margin.
  • The broad except Exception catches genuine bugs as readily as convergence failures. The note preserves the exception type, which is usually enough to tell them apart — but a TypeError in a bench will be reported as a measurement failure rather than crashing, and it is on the reader to notice.
  • It never raises. For a caller that wants an exception on an unsized device, sized_netlist() is the strict path.
