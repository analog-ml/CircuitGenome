Part 1 · Why this file exists

TLDR: deck.py turns a generic sized netlist into one runnable block of SPICE — choosing the right model idiom for the technology, writing the solved geometry into every device, rewriting MOSFETs as subcircuits when the PDK demands it, and keeping track of where the operating-point probes moved to when it did.

generic netlist + sizing + tech → one runnable DUT block

Part 2 · _emit_model() — three technologies, three idioms

Main task: write .includelines

CircuitGenome supports three quite different notions of "technology", and they need three different SPICE preambles:

if tech.spice_lib:                       # foundry PDK (GF180, sky130)
    return f'.include "{lib.design}"\n' + f'.lib "{lib.file}" {corner}\n'
if tech.spice_model:                     # PTM: flat .model cards
    return f'.include "{tech.spice_model}"\n'
# card-less "generic": synthesise a Level-1 card from the tech YAML
return f".model nmos nmos level=1 kp={n.mu_cox} vto={n.vth} lambda={n.lam} …"

The generic branch is the interesting one

For the card-less generic technology there is no model file — the tech YAML carries only µCox, Vth and λ. So the file writes a Shichman-Hodges (level=1) card from exactly those three numbers, with gamma=0 and phi=0.7 pinned.

That choice is deliberate and it is what makes the verification meaningful per technology:

TechnologySPICE seesSo the SPICE–analytical delta measures…
generica Level-1 card built from the same µCox/Vth/λ…almost nothing — it is a self-check that the deck and the formulas agree
ptm45the real BSIM4 card…the square-law-vs-real-device gap
gf180mcu, sky130the foundry corner library…the same gap, plus real process corners

The corner argument only bites on the PDK branch: it overrides the tech's nominal corner so a caller can re-measure the same sized design at ss, ff, sf and fs without re-sizing it.

Part 3 · Injecting the solved sizes — and refusing to guess

The one job: write each device's chosen W/L (and each capacitor's chosen value) into the netlist lines — and notice loudly if some device has no chosen value at all.

_inject_sizes() walks the subcircuit body and rewrites each device line from the SizingResult: MOSFETs get W=/L=, compensation capacitors get Cc, sized load resistors get their resistance.

The neighbouring function is the one worth knowing about:

def unsized_mos_refs(body, result) -> list[str]:
    """MOSFET refs in `body` that `_inject_sizes` would leave unsized."""
    return [tok[0] for line in body
            if … and tok[0] not in result.transistors]

Why an unsized device is worse than a crash

If a MOSFET in the netlist has no entry in the sizing result, _inject_sizes leaves its line untouched — and ngspice happily simulates it at the simulator's default W/L. That is the worst possible failure mode: silent and plausible.

So the two entry points that build decks treat it differently, on purpose:

  • sized_netlist() — used to export a design — raises ValueError. An exported netlist that claims to be sized must be fully sized.
  • simulate_metrics() — used to measure — records a note and continues, because a partial measurement with a warning beats no measurement.

Part 4 · The PDK rewrite — when a transistor is a subcircuit

The one job: a foundry device is not a .model MOSFET. Rewrite every generic device line into the PDK's own instantiation syntax.

PTM ships flat .model nmos cards, so a device line stays a device line. A foundry PDK does not: nmos_3p3 is a subcircuit, and SPICE instantiates subcircuits with x, not m. _emit_body() performs that translation, and it is a no-op unless the tech carries a device_map.

The consequence that is easy to miss

Once a device is a subcircuit, it is no longer where ngspice's operating-point probes expect to find it. A flat MOSFET answers to @m.xdut.m1_load[id]; a PDK device is one level deeper, inside the subcircuit, under whatever internal name that cell uses. _dev_prefix() is the one place that knows this:

if tech.device_map:
    handle = (tech.device_handle or {}).get(model, "m0")
    return f"@m.xdut.{_xref(ref)}.{handle}"   # one level deeper
return f"@m.xdut.{ref}"                        # flat

GF180's cells use m0; sky130 names its internal device per cell (msky130_fd_pr__nfet_01v8), which is why device_handle is a per-model table rather than a single string.

Part 5 · _run() — actually invoking the simulator

The one job: hand a deck to the ngspice binary and get numbers back — or None.

Two runners, because the benches want two different things out of ngspice:

  • _run(deck, vectors) — the deck writes numeric columns with wrdata; the runner loads them into a NumPy array. This is what every AC/transient bench uses.
  • _run_capture(deck) — returns ngspice's raw stdout as text, for decks that print operating-point values that then get parsed with a regex. This is what op.py uses.

Both return None rather than raising when the simulator fails, exits non-zero, or writes nothing parseable. That is the package's central convention and it starts here: the absence of a measurement is data, not an error.

And before any of it, ngspice_available() — a one-line shutil.which check — lets callers skip the whole path cleanly when the binary is not installed, which is why the test suite degrades to "skipped" rather than "failed" on a machine without ngspice.
