Part 1 · Why this file exists

The one job: put the sized circuit into six different states, and read one number (or three) out of each.

You cannot measure all of this at once, and the file does not try.

Quiescent power wants a DC operating point. Gain wants a small-signal sweep about that point. Slew rate wants a large step that deliberately leaves the small-signal regime. Output swing wants the input ramped across the supply. CMRR and PSRR want the same AC sweep as gain, with the stimulus moved somewhere else entirely.

Those are six incompatible requests. So there are six benches, each assembling its own deck through rig.py and running its own ngspice invocation. The cost is six process launches; the payoff is that a circuit whose AC sweep will not converge still reports honest power and swing.

Part 2 · Which input is the non-inverting one?

The one job: the netlist has in1 and in2 and no opinion about which is which. Find out by experiment, before measuring anything.

Close a feedback loop around the wrong input and you have not built an amplifier — you have built a latch. The output slams to a rail and stays there. Every subsequent measurement is then a careful characterisation of a circuit sitting in a corner.

So the AC bench tries both assignments and asks a blunt DC question of each:

for inp, inn in _POLARITIES:               # (in1,in2) then (in2,in1)
    …
    dc = _deck(…, "op\nlet vchk=…\nwrdata __OUT__ vchk")
    vchk = float(_run(dc, ["vchk"]).flatten()[-1])
    ok = (abs(vchk) < 0.3*vdd) if topo.fd else (0.1*vdd < vchk < 0.9*vdd)

Negative feedback holds the output near the common mode. A latched output sits near a rail. That one comparison separates them — and for a fully-differential circuit the equivalent question is whether the difference is near zero.

Settling is necessary, not sufficient

A branch that settles still might not be the right one, so the winner is chosen by a two-key rank:

rank = (_pm_plausible(pm), gain_db)
if best_rank is None or rank > best_rank:
    best, best_rank, best_pol = (gain_db, gbw, pm), rank, (inp, inn)

Plausibility first, gain only as a tie-break. That ordering is the whole point: a corrupted branch can easily report a higher gain than the honest one, and ranking on gain alone would hand the measurement to the artefact. The winning polarity is then returned so the slew, swing, CMRR and PSRR benches never have to rediscover it.

Part 3 · The AC sweep, and two decisions inside it

The one job: sweep frequency, find where the gain crosses 0 dB, and read the phase there.

The deck dumps real and imaginary parts and NumPy does the rest — magnitude by hypot, phase by unwrap(arctan2(…)). Two choices in those few lines are worth pulling out, because both were bugs at some point.

Starting at 1 mHz, not 1 Hz

ac dec 30 1e-3 1e10

A high-gain multi-stage amplifier can have a dominant pole well below 1 Hz. Start the sweep at 1 Hz and your first sample is already past it: the "DC" gain you report is rolled off, and — worse — the phase baseline is skewed by tens of degrees, which lands directly in the phase margin. Starting three decades lower makes the first sample a genuine DC value.

Phase measured relative to its own DC value

phase = np.degrees(np.unwrap(np.arctan2(im, re)))
phase -= phase[0]                # ← the baseline is the sweep's own DC phase

An inverting configuration starts at ±180°, a non-inverting one at 0°. Subtracting the first sample removes that unknown offset, so what remains is excess phase — the part the poles contributed. Then:

PM = 180° + phase(f0dB)

Excess phase is negative on a stable amplifier, so PM lands below 180°. The 0-dB crossing itself is found by linear interpolation in log-frequency between the samples that straddle it, and the phase is interpolated at the same fraction.

Part 4 · _pm_plausible() — telling a bad circuit from a bad measurement

The one job: decide whether a phase margin is physically possible — and if it isn't, work out which kind of impossible.

return pm is None or 0.0 < pm <= 180.0

One line, three outcomes, and the distinction between them is the difference between a bug report and a design verdict:

Note also what happens to the gain when the PM is implausible: it is discarded too. The gain and the phase came off the same sweep, so if the phase is meaningless the gain is meaningless with it. Reporting a confident-looking gain from a sweep you have just declared corrupt would be the worst of both worlds.

Separately, a plausible measurement of a circuit that simply does not amplify — gain ≤ 0 dB — is reported, with a reason attached. That is a real property of a mis-biased design, and hiding it would be dishonest in the other direction.

Part 5 · _loop_fb() — and why the FD bench was rebuilt

The one job: hold the inputs at the right DC bias without shorting out the AC stimulus — differently for single-ended and fully-differential circuits.

Single-ended is the textbook trick: a huge inductor closes the loop at DC (setting the bias) and is an open at AC; a huge capacitor grounds the inverting input at AC. The loop is closed for biasing and open for measuring.

Fully-differential used to tie outp→inn and outn→inp. That is now understood to have been wrong in three separate ways:

  • It invented an output common mode for circuits that have a real CMFB loop to do that job. Against a real CM loop the tie network is bistable, and at tight headroom ngspice picks its degenerate all-off solution — healthy sky130 circuits were measuring −79 dB.
  • It made the FD DC sanity check vacuous: the ties force outp == outn, so "did the outputs split apart?" could never be true.
  • It measured a circuit nobody would build.

The rebuilt bench anchors both inputs at Vcm and lets the CMFB own the output CM — the standard FD arrangement. And it uses resistors to do it, not inductors, for a reason worth knowing:

fb = (f"Vocm ocm 0 {vcm}\nVicm icm 0 {vcm}\n"
      f"R1 icm inp {_RH}\nR2 icm inn {_RH}\n" + drive)

Two inductor anchors plus a 0 V differential drive would form a loop of three DC shorts — singular, which ngspice "regularises" into garbage bias. Resistors avoid that, and cost nothing: MOS gates draw no DC current, so the drop across _RH is exactly zero and the inputs sit precisely at Vcm.

The FD drive also deliberately omits AC-coupling capacitors on the inputs — they would short out the very differential signal being applied.

Part 6 · Slew rate — measuring the plateau, not the tail

The one job: find the current-limited rate the output can move, which is not the same as the average rate it moved.

Slew rate is what happens when the input step is big enough that the tail current saturates: the output ramps at a roughly constant I/C and the small-signal model no longer applies. The textbook measurement is the 20%–80% average of a large step.

That average is only correct if the whole 20–80 window sits inside the ramp. On an amplifier whose transient ends in a slow pole-zero-doublet settling tail, the 80% mark lands in the tail, and the "slew rate" collapses to the settling speed — measured 0.7 V/µs against a real current-limited plateau roughly forty times higher.

The running extreme (np.maximum.accumulate) is used to locate that crossing, so end-of-edge ringing cannot cut a window short. And the reported figure is the minimum of the rising and falling edges — an amplifier is only as fast as its slower direction.

Part 7 · Output swing — not through a unity buffer

The one job: find how far the output can actually go, without accidentally measuring the input stage instead.

The obvious rig is a unity-gain buffer with a swept input. It measures the wrong thing. In a buffer the input rides with the output, so the sweep stops when either the output saturates or the input leaves its common-mode range — and the result is the intersection of two unrelated limits, reported as one.

So the bench uses an inverting −1 network instead, with the non-inverting input pinned at CM:

fb = (f"Rfb out inn 10meg\nRin src inn 10meg\n"
      f"Vp inp 0 dc {vcm}\nVin src 0 dc {vcm}\n")   # sweep Vin, not the input pin

The input stage now sits still while the output is driven across the supply. Ten-megohm resistors keep the DUT's output effectively unloaded.

Reading the edges: the tracking region

You cannot just take the extremes of v(out) — past saturation the output stops following and the curve flattens at whatever the rail allows. Instead the bench finds where the loop is still working:

slope = np.gradient(vo, vin)
track = slope <= -0.7            # inverting: a tracking loop has slope ~ -1
…                              # walk outward from CM while track holds
return float(vo[lo]), float(vo[hi])

It starts at the CM sample and expands in both directions while the slope stays near −1. The values at the edges of that contiguous region are the reachable extremes. If the loop is not even tracking at CM, this polarity is wrong and the bench moves on.

Part 8 · CMRR and PSRR — ratios, and what that implies

The one job: measure the gain from somewhere the signal should not get in, and compare it to the gain from where it should.

Both are differences of decibels against the differential gain measured earlier:

CMRR = Adm − Acm    PSRR+ = Adm − Avdd

The rigs are the gain bench with the stimulus relocated. For CMRR the 1 V AC rides on the input common mode (SE: on the cm node itself; FD: both gates AC-coupled to one source). For PSRR it rides on VDD — which is the entire purpose of _rig()'s sup_ac flag.

Why they are gated on a clean AC measurement

Both are relative to adm_db. If the differential gain came from a corrupted sweep, the ratio is garbage divided by garbage — and it will still print as a confident-looking number. So the orchestrator only runs these two when the AC bench reported a clean, positive-gain result:

if ac_clean:                      # reason is None → positive gain, uncorrupted sweep
    out["cmrr_db"] = _measure_cmrr(…, adm_db=out["gain_db"])
    out["psrr_db"] = _measure_psrr(…, adm_db=out["gain_db"])

Each also guards its own denominator: an acm or avdd that comes back as numerical zero means nothing was measured, not that rejection was infinite, so the result is None rather than a spectacular figure.

Part 9 · What it honestly does not do

  • Slew rate and output swing are single-ended only. Both return None for a fully-differential circuit — the rigs have not been built.
  • PSRR is positive-supply only. There is no PSRR−.
  • Every measurement is at one operating point and one corner. Corners are re-measured by calling the whole thing again with a different corner, not by sweeping inside a bench.
  • The polarity search tries exactly two assignments. That is all a two-input amplifier has, but it does mean a circuit that settles under neither yields nothing at all — correctly, since there is no configuration in which it works.
  • None of these is sign-off. They are a fast, independent cross-check on the analytical estimate; a real design still needs a real verification flow.

In one sentence: measure.py puts one sized circuit into six different states to read nine numbers off it — discovering the input polarity by experiment first, refusing to report gain from a sweep whose phase is physically impossible, and measuring slew and swing with rigs chosen so they cannot quietly measure something else instead.
