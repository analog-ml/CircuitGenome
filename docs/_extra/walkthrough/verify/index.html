ngspice Verification — a package walkthrough

circuitgenome/sizer/verify/ — take a design the sizer has just sized, put it on a simulated bench, and measure what it actually does.

Every number the sizer reports about a circuit it just designed is a prediction. This package goes and measures.

The sizer works in closed form: a gain is gm · Rout, a phase margin comes from a two-pole approximation, a slew rate is I/C. Those formulas are fast enough to search thousands of candidate designs, and they are the reason the sizer can search at all. But they are a model of a transistor, and a real 45 nm device is not a square law.

So after a design is sized, verify/ writes out an ngspice deck for the sized circuit — the same technology, the same W/L the sizer chose — and measures the same nine quantities on a simulated bench. The delta between the two is the honest error bar on the analytical estimate.

Three ideas the package is built on

1 · Every metric gets its own deck

It would be cheaper to run one simulation and read nine numbers off it. The package doesn't: power, the AC sweep, slew, swing, CMRR and PSRR each assemble and run a separate ngspice invocation, because each wants the circuit in a different state — a DC operating point, an AC sweep about that point, a large-signal step, a DC input ramp. Sharing one deck would mean compromising all of them.

It also buys isolation. A design whose AC sweep diverges still reports its quiescent power honestly, because those two facts were never computed together.

2 · A failed measurement is None, never an exception

This is best-effort verification, not sign-off. ngspice fails to converge on real circuits for real reasons, and a verification pass that raises on the first non-convergence is useless for a search over thousands of candidates. Every bench is wrapped; a failure records None plus a human-readable note, and the sweep continues.

The corollary matters when reading results: None means "not measured", never "measured as zero".

3 · The bench must first find the circuit's polarity

A synthesized netlist has two input pins, and nothing in it says which one is non-inverting. Wire the feedback to the wrong one and the bench measures a latched output rather than an amplifier. So the AC testbench tries both, keeps whichever settles to a sane DC operating point with a physically plausible phase margin, and hands that polarity to every later bench. Getting this wrong is the difference between −79 dB and a healthy measurement.
