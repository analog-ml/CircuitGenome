Part 1 · Why this file exists

The one job: six testbenches all need the same scaffolding around the DUT — a supply, a bias current, and a wiring map. Write it once. Then handle the two things about that scaffolding which are not the same for every circuit.

The boring part is boring. The interesting part is what refuses to stay constant.

deck.py hands over a DUT block: a .subckt with real device sizes and a real model card. It is inert. To measure anything you have to surround it with a bench — power it, bias it, drive it, and connect its pins to the nets your stimulus lives on.

Most of that is identical across the six benches, and this file factors it out. But two pieces are circuit-dependent in a way you cannot read off the netlist directly, and both will silently ruin a measurement if you guess:

  • Which input is non-inverting? The netlist has in1 and in2. Nothing says which is which.
  • Which way does the bias current flow? Push current into a pin that wants to source it, and the entire bias generator goes dead.

The first is resolved by experiment in measure.py; the second is resolved by inspection, here.

Part 2 · _Topo — what the pin list tells you

The one job: decide, from the port names alone, whether this is a single-ended or a fully-differential amplifier — and whether it expects a common-mode reference.

class _Topo:
    def __init__(self, ports):
        self.ports   = ports
        self.fd      = "outp" in ports and "outn" in ports
        self.out     = ["outp", "outn"] if self.fd else ["out"]
        self.has_vcm = "vcm_ref" in ports

Twelve lines, and every bench branches on them. A fully-differential circuit needs its output read as a difference (v(outp)-v(outn)), needs both outputs checked for railing, and — if it exposes vcm_ref — needs that pin driven to the common-mode voltage or its CMFB loop has no reference to servo against.

has_vcm is separate from fd for a real reason: when a fully-differential topology has its CMFB pruned, the vcm_ref pin goes with it. So "is differential" and "wants a CM reference" are two questions, not one.

Part 3 · _iref_sink() — which way does the bias current go?

The one job: look at the reference diode on the ibias pin and decide whether the bench must push current in or pull it out.

Every amplifier here is biased from a single external reference current on the ibias pin. Inside, that pin lands on a diode-connected MOSFET — d == g == ibias — which mirrors the current to everything else. The question the bench has to answer is which rail that diode sits on, because it flips the direction of the whole thing.

What happens if you get it wrong

Inject into a PMOS-referenced generator and the diode is already conducting from vdd; the injected current has nowhere to go, so the pin is driven above the supply. Every mirror hanging off it turns off. The deck simulates fine and reports an amplifier with no bias at all.

So the function reads it off the device lines rather than assuming:

rails = set()
for line in dut_lines:
    tok = line.split()
    if len(tok) >= 6 and tok[1] == tok[2] == "ibias":    # d == g == ibias
        s = tok[3].lower()                                 # the source rail
        rails.add("vdd" if "vdd" in s else "gnd")
return rails == {"vdd"}                                  # sink only if unambiguously PMOS

Note the strictness of the final line. No reference diode at all, or conflicting diodes on both rails, falls back to injecting — the historical behaviour. The function only overrides when the evidence is unambiguous, which is the right instinct for a heuristic that reads raw text.

It also works on both raw and PDK-rewritten lines, because the m→x rewrite preserves the ref d g s b model token order — only the prefix and the model name change.

Part 4 · _fb_netmap() and _deck() — assembly

The one job: map the DUT's pins onto the bench's nets for a chosen input polarity, then concatenate everything into one string ngspice can run.

The netmap is the join between two naming worlds. The DUT speaks in port names (in1, vdd!, outp); the bench speaks in net names (inp, vdd, outp). One dict reconciles them, parameterised by which port is playing the non-inverting role:

netmap = {"ibias": "ibias", "vdd!": "vdd", "gnd!": "0",
          inp: "inp", inn: "inn"}          # ← the polarity lives here

Swapping the polarity is nothing more than passing (in2, in1) instead of (in1, in2). That is what makes trying both cheap enough to do by brute force.

Part 5 · What it honestly does not do

  • It does not find the input polarity. It only makes both choices equally easy to wire, so the AC bench can try them and pick. See measure.py.
  • The bias-direction heuristic is textual. It looks for d == g == ibias in the device lines; a bias generator that references its current some other way would not be recognised, and the fallback is to inject.
  • Both rails carrying a reference diode is treated as "unknown", not "both". That case is not expected to occur, and if it ever does the fallback quietly hides it.
  • Nothing here is a measurement. Every function returns a string; not one of them runs a simulator.

In one sentence: rig.py is the boilerplate every testbench would otherwise repeat — supplies, bias source, pin-to-net wiring and deck assembly — plus the one piece of real circuit reasoning that boilerplate needs: reading the reference diode's rail to decide whether the bias current must be pushed in or pulled out.
