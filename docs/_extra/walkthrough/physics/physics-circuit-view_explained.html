Part 1 · Why this file even exists

The one job: turn the recognizer's output into the one structural picture every sizer starts from — which devices are in which slot, one entry per distinct device, and a warning if the circuit does not look like the topology it claims to be.

The idea, before any code.

The recognizer hands over a pile of slot assignments. Before anyone can choose a width, four questions have to be answered: which transistors are in each slot, which resistors, which devices are actually distinct (a device can appear in two slots), and does the shape match the template.

None of that is hard. What is easy to get wrong is the order, because one step patches the slot map and three later steps read it. Do them in the wrong sequence and a device silently vanishes from the roster, the dedup map and the warnings at once — and an unsized transistor runs at the simulator's default geometry, which is nobody's intent.

So the four steps are private and the answer arrives as one value:

view = analyze_circuit(fbr_result, topology)
view.slot_transistors   # slot -> [Device]
view.slot_resistors     # slot -> [Device]
view.all_transistors    # ref  -> (Device, owning slot)
view.warnings           # topology-mismatch advisories

A caller asks once and gets a consistent set. The gm/Id pipeline needs two more things — a typed block decomposition and the cascode refs — so it extends this view rather than assembling its own; see gmid/analyze.py.

Part 2 · Slot extraction — the humble first step

The one job: the recognizer already grouped devices into named slots (input_pair, load, tail_current…); these two functions just fish the MOSFETs (or the resistors) out of each slot into a tidy {slot: [devices]} dictionary.

def extract_slot_transistors(fbr_result) -> dict[str, list[Device]]:
    result = {}
    for slot_name, sa in fbr_result.slot_assignments.items():
        mosfets = [d for d in sa.structure.devices if d.type in ("nmos", "pmos")]
        if mosfets:
            result[slot_name] = mosfets
    return result

Analogy: the recognizer handed us a set of labeled drawers (a drawer marked input_pair, one marked load, …). Each drawer is a jumble of parts. This function walks every drawer and keeps only the transistors, skipping caps, resistors, and anything else. extract_slot_resistors is the identical walk, but it keeps type == "resistor" instead.

The one subtlety: a slot with no matching device is dropped, not stored as an empty list. That's the if mosfets: guard. So later code can write slot_transistors.get("load", []) and trust that a present key always has at least one device — a small invariant that removes a lot of "is it empty?" checks downstream.

That empty-drop rule is the whole cleverness. Everything that follows leans on it.

Part 3 · _adopt_orphan_mosfets() — catching the strays

The one job: a transistor the recognizer could not place belongs to some slot. Find it a home before anything else reads the slot map.

Pattern matching is not perfect. A device can fall out of every slot when its structure is ambiguous — two identical parallel diodes on one net — or incomplete, like a load whose expected partner has been pruned away. The consequence is silent and bad: a device in no slot never gets sized, so ngspice runs it at its default W/L and the measured circuit is not the designed one. Worse, the analytical metrics never see its output conductance, so the predicted gain comes out higher than the real circuit can deliver.

This is not a rare safety net, but it is a narrow one. Sweeping all 13 topologies — 4,540 circuits — strays appear in 162 of them, and every single one belongs to a two-stage fully-differential topology: 54 of 400 plain, 108 of 400 buffered. The three-stage fully-differential topologies are clean, as is everything single-ended. The shape is always the same: CMFB has been pruned, the load slot no longer matches, and both load transistors arrive here as orphans. Sizing one such circuit with this pass disabled reports about 5 dB more gain, from exactly those two uncounted devices.

Synthesized netlists name every device {ref}_{slot_name}, so an orphan carries its own address:

slot = next((s for s in slot_names if dev.ref.endswith("_" + s)), None)
if slot is not None:
    slot_transistors.setdefault(slot, []).append(dev)

Slot names are tried longest-first, so second_stage_p wins over second_stage. A device whose ref matches no slot — a hand-written or foundry netlist, which has no such convention — is left alone rather than guessed at.

Why it runs second, not fifth

This is the ordering constraint the whole module is arranged around. The raw slot map is built first; this pass patches it; and only then do dedup and the topology check read it. Both sizers inherit that order for free by calling analyze_circuit, instead of each having to remember it.

It reports, it does not paper over

An adoption means functional-block recognition could not place a device the netlist plainly contains. Sizing is correct afterwards, but the gap is real — and the rescue only works because synthesized netlists name devices {ref}_{slot}. Hand the same circuit in from outside with different ref names and nothing saves it.

So the pass returns what it adopted, the view carries it as view.adopted, and each sizer turns that into a warning on its result. It is deliberately not folded into view.warnings: a consumer that reads the first warning to explain why a candidate failed to bias should not be handed a recognizer advisory instead.

Part 4 · check_topology_match() — the sanity inspector

The one job: catch the case where the netlist you handed in does not actually realize the topology you asked to size for — and say so, loudly, instead of silently producing garbage gain/PM numbers.

Analogy: you asked the builder for a two-car garage, but the blueprint clearly shows one car space. Rather than pour a foundation that half-fits, the inspector stops and says "this blueprint doesn't match the order." That's this function.

The tell-tale sign of a valid gain stage: every stage slot holds exactly one signal transistor — a device whose gate is driven by the previous stage's output, not a bias rail. If a stage slot exists but contains no signal device (just bias-generator leftovers shoved in), the netlist doesn't match the chosen topology.

def check_topology_match(slot_transistors, topology_name) -> list[str]:
    warnings = []
    for slot in sorted(STAGE_SLOTS):
        devs = slot_transistors.get(slot)
        if devs and not any(is_signal_device(d) for d in devs):
            warnings.append(f"stage slot '{slot}' has no signal transistor …")
    return warnings

Why does this matter so much? Because the downstream gain, phase-margin, and PSRR math reads the second/third-stage signal device. If that device is missing, those metrics would silently drop out and the sizer would happily report numbers for a circuit it never actually sized. A concrete trigger: sizing a single-ended netlist against a fully-differential --topology, where a bias-generator leftover gets shoehorned into second_stage_p. The function doesn't fix it — it just refuses to be silent about it.

Note the if devs and …: an absent stage slot is fine (a two-stage amp simply has no third stage). Only a slot that exists but has no signal device trips the warning.

Part 5 · deduplicate_devices() — one ref, one home

The one job: a single physical transistor can appear in two slots at once; before we assign it a current, decide which slot "owns" it — the higher-priority slot wins.

Analogy: an employee is listed on two org charts (they help two teams). For payroll, you must pick exactly one home team so they don't get paid twice. This function picks that home team using a fixed priority list.

The classic collision: a tail-mirror reference transistor legitimately shows up in both tail_current and bias_gen. If we assigned current from both slots we'd double-count. So we impose an order and let the first slot encountered win.

def deduplicate_devices(slot_transistors) -> dict[str, tuple[Device, str]]:
    priority = ["input_pair", "load", "tail_current",
                "second_stage", …, "bias_gen"]
    ordered = sorted(slot_transistors.keys(),
        key=lambda s: priority.index(s) if s in priority else len(priority))
    seen = {}
    for slot in ordered:
        for d in slot_transistors[slot]:
            if d.ref not in seen:
                seen[d.ref] = (d, slot)     # first (highest-priority) slot wins
    return seen

The two-line trick worth admiring: sorted(..., key=priority.index) walks the slots in priority order, and if d.ref not in seen means a ref is claimed exactly once — by whichever high-priority slot reached it first. Unknown slots sort to the very end (len(priority)), so they only ever claim refs nobody else wanted.

The output shape — {ref: (Device, slot)} — is exactly what the next pass wants: a flat list of every unique transistor, each tagged with the one slot that decides its current.

Part 6 · analyze_circuit() — the assembly line

The one job: run the four steps in the one correct order and hand back a single value. It holds no logic of its own.

def analyze_circuit(fbr_result, topology) -> CircuitView:
    slot_transistors = _extract_slot_transistors(fbr_result)
    adopted = _adopt_orphan_mosfets(slot_transistors, fbr_result, topology)
    return CircuitView(
        slot_transistors=slot_transistors,
        slot_resistors=_extract_slot_resistors(fbr_result),
        all_transistors=_deduplicate_devices(slot_transistors),
        warnings=_check_topology_match(slot_transistors, topology.name),
        adopted=adopted,
    )

Every helper it calls is underscore-private. That is the point: the module's interface is this one function, so there is no way for a caller to run three of the four steps, or to run them out of order. Everything downstream — requirement derivation, the stage chain, the gm/Id block view — takes the finished CircuitView.

What it honestly does not do

  • It reads structure only. Not one current, width or voltage is decided here — that is preprocess.py and the sizers.
  • The topology check is advisory. A mismatch produces a warning, never a refusal: an unusual circuit is still sized, and the caller decides what the warning is worth.
  • Orphan adoption only works where refs carry slot suffixes, i.e. synthesized netlists. An external netlist with a genuinely unplaceable device still loses it.
